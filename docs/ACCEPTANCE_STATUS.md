# Acceptance evidence status

The full product is **not ready for public launch**. [acceptance-evidence.json](acceptance-evidence.json) maps every one of the handoff's 148 required scenarios to concrete assertions, test files, commands, proof records and remaining work. Every row initially started `NOT RUN`; `PARTIAL` means some evidence exists but the complete row has not been demonstrated. Neither a test title nor a green suite replaces a row's missing assertions.

This is an internal engineering evidence review dated 2026-09-27, not owner approval or an independent security assessment. The final source candidate is bound to SHA-256 `6fc9a70876182ae821f35d4022c37c3a1be32bdaf1c6cfb25646de9bc618318f` and production build `ifod-872AGPJhszNIz8RK`. Clean install, lint, typecheck, content validation, build, audit and secret scan passed. Final test counts are 28 unit, 30 database integration, 45 security, 24 browser and 17 automated accessibility checks. See [release-evidence.json](release-evidence.json) for command artifacts and hashes. These 144 automated test cases do not equate to the 148 complete acceptance scenarios.

The acceptance matrix currently records 8 PASS, 104 PARTIAL and 36 NOT RUN scenarios.

Observed local evidence includes exact equality of all 1,000 source ideas and 22 categories, deterministic public artifacts, real PostgreSQL/WASM constraints and RLS, real raster re-encoding, maintained CSRF token verification, and selected in-process API and browser assertions. The latest security run recorded here passes 45 tests across 10 files. The saved red/green regressions retain proof of the refresh-outage cookie fix and private upload compensation wiring.

PGlite executes actual PostgreSQL semantics but does not prove postgres.js TCP pool reuse or multi-instance concurrency. Provider and worker mocks prove only the recorded application decisions and ordering. They do not prove real email delivery, CAPTCHA consumption, signature/MFA/provider settings, storage policy enforcement, signed URL expiry, actual object deletion, schedules or alert delivery. Axe scans and screenshots do not establish manual accessibility or owner visual approval.

The separate [ASVS register](asvs-5.0-l2-evidence.json) inventories all 253 Level 1 and Level 2 requirements from the [official versioned OWASP ASVS 5.0.0 source](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/docs_en/OWASP_Application_Security_Verification_Standard_5.0.0_en.flat.json). It contains 124 partial mappings and 129 unverified controls, including 36 proposed exclusions that nobody has approved. It makes **no ASVS compliance claim**. Each exact control retains its source identity and statement hash. OWASP's source is licensed [CC BY-SA 4.0](https://github.com/OWASP/ASVS/blob/v5.0.0/LICENSE.md); this derived register preserves that attribution and is offered under the same license.

The control register exposes additional review questions: ordinary member email-only authentication versus ASVS 6.3.3, raster re-encoding without an antivirus service versus 5.4.3, configured service credentials versus the short-lived identity requirement in 13.2.1, and complete active-session inventory/termination under 7.5.2. These are unresolved applicability or implementation assessments, not approved exceptions.

Required follow-up includes genuine reviewed timeline articles, real rights/legal/contact/operator inputs, production provider configuration and accounts, hosted direct-access/pool/cache/MFA tests, full member and moderator browser journeys, manual accessibility, independent security review, authorized resource/load measurements, and SQL-plus-object restore with deletion-ledger reapplication. Actual scheduling, retention/log/backup policy, monitored alerts, budgets, moderation coverage and owner production authority also remain gates. Runbooks describe these operations; they are not evidence that the operations have occurred.

Only an observed complete row may become `PASS`. Do not replace a failed check, unfinished review, missing infrastructure or unapproved exclusion with a success label to clear the release gate.
